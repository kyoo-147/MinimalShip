# MinimalShip glossary

## Outcome
The user-visible change or measurable improvement a cycle exists to create. An outcome is not a technology, task list, or number of agents.

## User journey
The concrete path from a real input through the product to a useful result, including the failure state that matters.

## MUST / NOT NOW
The smallest accepted boundary for the current cycle and the work intentionally deferred. NOT NOW is not a hidden promise.

## Acceptance case
An observable input, action, and expected result that can be marked PASS, FAIL, or BLOCKED with evidence.

## Vertical slice
A thin end-to-end path that crosses the necessary layers and produces a real result.

## Seam
A public boundary where behavior can be observed or replaced without reaching into private representation.

## Deep module
A module that hides substantial policy or complexity behind a small, honest interface.

## Task envelope
The bounded worker contract containing user value, ownership, interfaces, exclusions, verification, and finish evidence.

## Decision frontier
The currently answerable questions in a dependency-ordered product or architecture decision tree.

## Orchestrator
An optional runtime integration that starts, supervises, or routes worker agents. It is not the product owner and it does not determine acceptance.

## Evidence
A command result, reproducible observation, user feedback, metric, log, screenshot, or review finding that supports a claim. Plans and spinners are not evidence.

## BLOCKED
A required action or check cannot proceed because a specific dependency, permission, environment, or decision is missing. BLOCKED is not PASS.
