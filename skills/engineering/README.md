# Engineering

Product-development skills in this bundle.

## User-invoked

- **[ask-minimalship](./ask-minimalship/SKILL.md)**: Choose the smallest MinimalShip flow for a product-development task.
- **[grill-with-docs](./grill-with-docs/SKILL.md)**: Resolve consequential product and architecture ambiguity while maintaining the project's vocabulary and decision records.
- **[setup-minimalship](./setup-minimalship/SKILL.md)**: Configure a repository for the MinimalShip product-development workflow without imposing an issue tracker or hosted service.
- **[to-spec](./to-spec/SKILL.md)**: Turn an already-discussed product request into a compact, testable specification without restarting discovery.
- **[to-tickets](./to-tickets/SKILL.md)**: Break a product spec into small tracer-bullet work items with explicit dependency edges and acceptance checks.
- **[implement](./implement/SKILL.md)**: Build one accepted product slice from a spec or bounded work item and close it with evidence.
- **[implement-spec](./implement-spec/SKILL.md)**: Execute a complete spec as a dependency-aware task graph on one integration branch.
- **[improve-codebase-architecture](./improve-codebase-architecture/SKILL.md)**: Survey a codebase for high-leverage module deepening opportunities and turn one selected opportunity into an actionable change.
- **[triage](./triage/SKILL.md)**: Move product and engineering reports through a small evidence-based state machine.
- **[wayfinder](./wayfinder/SKILL.md)**: Plan a large, multi-session product initiative as a map of decisions and bounded delivery slices.
- **[retro](./retro/SKILL.md)**: Review a completed coding session and propose the smallest environment improvement with evidence.

## Model-invoked

- **[codebase-design](./codebase-design/SKILL.md)**: Design deep modules and testable seams by hiding complexity behind small, honest interfaces.
- **[diagnosing-bugs](./diagnosing-bugs/SKILL.md)**: Use a disciplined reproduce, minimize, instrument, fix, and regression-test loop for hard bugs and performance regressions.
- **[domain-modeling](./domain-modeling/SKILL.md)**: Build a shared product vocabulary and keep code, acceptance, and decisions aligned with it.
- **[prototype](./prototype/SKILL.md)**: Build a disposable prototype to answer one product, state, interaction, or architecture question.
- **[research](./research/SKILL.md)**: Investigate a product or engineering question using high-trust sources and a concise evidence-linked note.
- **[tdd](./tdd/SKILL.md)**: Use a behavior-first red, green, refactor loop at agreed public seams.
- **[code-review](./code-review/SKILL.md)**: Review a diff on standards and product-spec axes, with separate evidence for correctness, scope, and design risk.
- **[pr](./pr/SKILL.md)**: Write a concise pull request that explains the user outcome, proof, risk, and merge decision.
- **[wizard](./wizard/SKILL.md)**: Generate a safe interactive shell wizard for steps only a human can complete, such as credentials or provider dashboards.
