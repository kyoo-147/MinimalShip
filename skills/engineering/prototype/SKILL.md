# Prototype

1. Write the one question the prototype must answer.
2. Choose the cheapest medium: throwaway script, HTML page, state model, or spike.
3. Define the observation that would change the next decision.
4. Build one path and include the failure state that matters.
5. Run it with representative input and record what changed.
6. Delete it, keep it as a named experiment, or start a production spec from the evidence.

The prototype earns its existence by reducing uncertainty, not by accumulating features.
